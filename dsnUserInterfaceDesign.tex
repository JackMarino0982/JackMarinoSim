\paragraph{Visible information.}
Display mode, current code, validity, sample age, sequence number, connection
state, recording state and loss/error indications. Preserve timing-quality
information so age/time are not presented as trustworthy when unknown or
unqualified; exact representation is TBD. Distinguish unavailable hardware
from a simulated connection. An explicit Live, Simulator or Replay mode must
remain understandable throughout the workflow; replay must not make the live
sensor appear healthy. Exact screen layout and refresh interval remain TBD.

\paragraph{Pending interface decisions.}
Control layout, file dialogs, keyboard behavior, error wording, concurrency,
protected settings and authorization implementation remain TBD. The controls
do not select hardware sample rates, buffer/drop policy, voltage scaling,
playback speed, an OMS message or supported operating-system versions.

\ChapterRef{Validation}; this owner approval does not complete those activities.

\section{Example}
Persona: a busy operations coordinator needs to submit and track requests quickly. The request screen groups required fields, identifies inline validation errors, confirms successful submission, supports keyboard operation, and exposes empty, loading, error, and completed states.
